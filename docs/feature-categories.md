# 功能规划 — 文档自定义归类（分类）

> 状态：已实现并通过验证（阶段四完成）
> 前置文档：`docs/product-spec.md`、`docs/design-contract.md`

## 1. 背景与目标

当前书架只能用「全部 / PDF / MARKDOWN / 收藏」四个内置维度筛选，这两个维度都是**文档自身属性**（类型、收藏），用户无法表达自己的组织意图。当书架超过 20 份文档后，"按最近打开排序的一长条列表"就失去了导航能力——用户找一份上周读的论文，只能靠搜索关键词。

**目标**：给用户一层**自定义归类**，让书架从「时间流水」变成「自己整理过的书架」。

**成功判据**（可观测，不靠感觉）：

| 指标 | 目标 |
| --- | --- |
| 归类操作耗时 | 单份文档拖到分类 ≤ 2 次动作 |
| 批量场景 | 一次操作可归类任意多份文档 |
| 旧数据兼容 | 升级后 `state.json` 无需迁移即可读取，原书全部变为「未分类」 |
| 零破坏 | 原有筛选 / 搜索 / 收藏 / 进度 行为完全不变 |

## 2. 范围

### 2.1 本期做

1. 分类的增 / 删 / 改（名称、配色）
2. **单一分类**：一份文档只属于一个分类，可为「未分类」
3. 书架面板内独立的**分类区**，带计数、点击筛选
4. **拖拽归类**：把文档拖到分类行上
5. **批量归类**：多选后一次性归类
6. **分类配色**：每个分类一个色点，取自固定色板

### 2.2 本期不做（明确取舍）

| 不做的能力 | 理由 |
| --- | --- |
| 多标签 / 多对多归类 | 用户已确认单一分类模型；多标签会让筛选语义退化成集合运算，与「书架的直觉」冲突 |
| 嵌套分类（树形） | 单一分类 + 树会产生「父分类是否包含子分类文档」的二义性；先验证平铺够用 |
| 分类拖拽排序 | 与「拖文档到分类」共用一套拖拽手势，容易误触；分类量级小（上限 40），按创建时间排序已够 |
| 按分类自动分组显示（分组视图） | 会改变书架主区结构（继续阅读 / 统计 / 网格），风险远大于收益；筛选已能满足导航诉求 |
| 分类持久化到界面还原 | 与现有 `state.filter` 一致：筛选态不落盘，重启回到「全部」。落盘会让用户重启后看到空列表却不知为何 |
| 智能分类 / 按目录自动归类 | 需要猜测用户意图，误归类比不归类更烦人 |

## 3. 数据模型

### 3.1 Rust 侧（`src-tauri/src/store.rs`）

```rust
/// 用户自定义分类
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct Category {
    pub id: String,
    pub name: String,
    /// 色板键：clay | indigo | olive | amber | plum | slate
    pub color: String,
    pub created_at: u64,
}
```

`Book` 增加一个字段：

```rust
    /// 所属分类 id；空串表示「未分类」
    #[serde(default)]
    pub category_id: String,
```

`AppState` 增加：

```rust
    #[serde(default)]
    pub categories: Vec<Category>,
```

**三个关键决策：**

1. **`category_id` 用空串而非 `Option<String>`**。序列化后不会出现 `null`，前端比较统一为 `=== ""`，少一层判空；「未分类」是一个真实可寻址的状态而非「缺失」。
2. **不引入 `order` 字段**。本项目已有过一次「声明了字段但从不写入」的教训（`Settings.split`），规划阶段就不重复。分类按 `created_at` 升序排列，将来真要做拖拽排序时再一并加字段与迁移。
3. **完全不写迁移代码**。`AppState` 已有容器级 `#[serde(default)]`，`Book` 的新字段单独标 `#[serde(default)]`，旧 `state.json`（无 `categories`、无 `categoryId`）可直接反序列化：`categories` 变空数组，所有书 `categoryId` 变 `""` —— 正好等于「全部未分类」，语义上就是用户升级前的事实。

### 3.2 磁盘形态

```json
{
  "version": 1,
  "categories": [
    { "id": "c1a3f2", "name": "论文", "color": "clay", "createdAt": 1762300000000 },
    { "id": "c1a3f3", "name": "技术手册", "color": "olive", "createdAt": 1762300001000 }
  ],
  "books": [
    { "id": "8f2b…", "title": "…", "categoryId": "c1a3f2", "progress": { … } }
  ],
  "settings": { … }
}
```

- 分类 id 用 `now_ms()` 的十六进制 + 序号，保证同一毫秒内批量创建也不撞车；不复用 `book_id` 的路径哈希（分类没有路径）。
- `version` 保持 `1`：本次是**向后兼容的字段追加**，不构成 schema 破坏，改版本号反而会让不认识的旧版二进制拒绝读取。

### 3.3 引用完整性

`book.categoryId` 指向的分类被删除时，**必须**在同一把锁内把所有指向它的书重置为空串，否则会出现「书属于一个不存在的分类」的悬挂引用。删除命令负责这件事（见 4.1 的 `delete_category`）。

## 4. 技术方案

### 4.1 后端命令（`src-tauri/src/commands.rs`）

| 命令 | 签名 | 返回 | 说明 |
| --- | --- | --- | --- |
| `get_categories` | — | `Vec<Category>` | 启动时与 `get_library` / `get_settings` 并发读取（实现阶段补充：分类需要独立的读取入口，避免改变 `get_library` 的返回结构） |
| `create_category` | `name: String, color: String` | `Category` | trim 后校验；重名（忽略大小写）拒绝；数量上限 40 |
| `update_category` | `id: String, name: String, color: String` | `Category` | 改名 + 改色一个命令搞定，减少往返 |
| `delete_category` | `id: String` | `Vec<Book>` | 同时把该分类下的书重置为未分类，返回更新后的书架 |
| `assign_category` | `ids: Vec<String>, category_id: String` | `Vec<Book>` | 批量归类；`category_id` 为空串即「移出分类」 |

- 四个命令都遵循现有模式：`lock()` → 改内存 → `store::persist()` → 返回快照。
- **`assign_category` 一次性接收数组**，而不是在前端循环调用单条命令：10 份文档就是 10 次写盘，中途失败会留下半归类状态。
- 校验统一放在 Rust：名称 trim 后为空、超过 20 字符、重名，都返回中文错误串，前端直接 `toast`。前端只做「按钮禁用」这类轻量防御，不作为唯一关卡。
- `lib.rs` 的 `generate_handler!` 追加这 4 项。

### 4.2 前端模块划分

遵循现有「一个文件一件事」的边界（见 `docs/dev-plan.md` 决策 7）：

| 文件 | 新增/改动 | 职责 |
| --- | --- | --- |
| `src/js/categories.js` | 新增 | 分类的**纯计算**：排序、计数、按分类过滤、找下一个色板颜色。不碰 DOM、不发请求 |
| `src/js/category-ui.js` | 新增 | 分类区的**渲染**：列表 DOM、创建/编辑弹层 |

| `src/js/shelf.js` | 改动 | `visibleBooks()` 增加分类轴过滤；渲染行时带 `draggable` 与分类色点 |
| `src/js/core/session.js` | 改动 | 追加 `categoryId`（当前筛选）、`selected: []`（批量选中的书 id） |
| `src/js/bind/category.js` | 新增 | 分类区事件：选中筛选、单击编辑、拖拽落点、批量提交、键盘 Esc |
| `src/js/bind/shelf.js` | 改动 | 书行的 `dragstart`、Ctrl/Cmd+点击多选 |

**依赖方向**：`categories.js`（纯函数）← `category-ui.js` / `shelf.js`；`actions.js` 是唯一的写入口，调用后 `renderLibrary()`。不允许 UI 模块自己 `invoke`。

### 4.3 筛选语义：类型轴 × 分类轴正交叠加

现有 `state.filter` 是**类型轴**（all / pdf / markdown / star），新增 `state.categoryId` 是**分类轴**（`null` = 全部分类 / 分类 id / `""` = 未分类）。两者 `AND` 组合：

```js
// shelf.js · visibleBooks()
if (state.categoryId !== null && book.categoryId !== state.categoryId) return false;
```

选择理由：两个维度互相独立（「我想看 PDF 里属于论文的那些」是真实诉求），互斥式设计会逼用户二选一。代价是可能组合出空结果，因此必须给出**组合态提示**：

- `#gridHead` 的标题从「全部文档」变为可读组合，如「论文 · PDF」；
- 组合非默认时，标题右侧显示「清除筛选」，一次点击把两轴复位；
- 空结果时空态文案区分两种情况：「这个分类下还没有文档」（分类非空但为空）与「没有匹配的文档」（搜索词导致）。

`renderResume` 与 `renderStats` **保持全局口径**（与现有 chip 筛选行为一致）：它们是「书架概览」，跟着筛选跳动会让人失去方位感。

### 4.4 拖拽归类

- 书行与网格卡片都设 `draggable="true"`，`dragstart` 写入 `dataTransfer.setData("application/x-yuejian-book", id)`，并同时写 `text/plain`（WebView2 对自定义 MIME 偶有不认）。
- 分类行作为落点：`dragenter`/`dragover` 时 `preventDefault()` 并加 `.is-drop`；`drop` 时读 id → `assignCategory([id], categoryId)`。
- **与现有文件拖入不冲突**：全局导入走的是 Tauri 的窗口拖放事件（`bind/panels.js` 里 `payload.type !== "drop"`），与 HTML5 内部拖拽是两套通道；但 `dragstart` 仍要 `stopPropagation()`，避免触发窗口级 drag 判定。
- 拖拽过程中，源书行加 `.is-dragging`（半透明）；落点分类行高亮 2px 朱砂描边 + 底色。
- 「未分类」行同样是合法落点，语义 = 移出分类。
- 拖拽只是快捷方式，**不是唯一路径**——批量归类必须能完成同样的动作（键盘用户 + 拖拽失手的兜底）。

### 4.5 批量归类

- `Ctrl`（macOS `Cmd`）+ 点击书行 → 切换该书的选中态，**不打开文档**；普通点击行为不变。
- 有选中项时，书列表顶部浮出批量条：`已选 N 项` + `归类到…`（下拉出分类列表）+ `取消`。
- `Esc` 清除选中；切换视图 / 刷新书架后选中态清空（避免对已移除的 id 操作）。
- 批量条里的分类下拉与拖拽落点走同一个 `assignCategory(ids, categoryId)`。
- 不实现 Shift 范围选择：列表按最近打开排序，范围选择的语义不稳定，收益低于复杂度。

### 4.6 分类的增删改

- 分类区头部右侧一个 `＋` 图标按钮 → 打开编辑弹层（创建模式），自动选中下一个未使用的色板颜色。
- 分类行悬停显示 `⋯` 按钮 → 编辑弹层（编辑模式：名称 + 配色）。
- 创建与编辑**共用同一个弹层**：都需要「名称 + 配色」两个字段，内联输入框放不下色板。创建速度快一点的诱惑不足以换来两套 UI。
- 弹层校验：名称 trim 后 1–20 字符、不可与其它分类重名（忽略大小写）；不满足时确认按钮置灰并给出原因，不发请求。
- 删除在编辑弹层里，红色文字按钮；点击后走 `askConfirm` 二次确认，文案必须写清「文档不会被移除」。
- 颜色自动分配规则：按色板顺序取第一个「当前分类里没人用」的颜色；全用满了就按数量取模循环。

### 4.7 分类区布局约束

书架面板宽 304px（窄屏 262px）。类型筛选与分类共用一个可滚动目录 `.shelf-index`（横排 pill 在这个宽度下必然挤字或裁切，故筛选走纵轴）：

- 位置：搜索框之下、`book-list` 之上；索引整体最大高 `min(344px, 42vh)`，超出内部滚动——不能让它把书列表挤没；
- 类型组默认收起，目录头自述当前选择（「类型 · PDF」）+ 该类型计数；展开后六行（全部 / PDF / Markdown / 文本 / 电子书 / 收藏），选中即自动收起；
- 分类组头部高 28px：「分类 N」+ `＋`；两组目录头双层吸顶（0 / 28px），滚动时不丢组上下文；
- 两组各保留自己的选中行（2px 朱砂竖条），类型 × 分类正交叠加不变；
- 可折叠（头部点击），折叠态只留头部一行；
- 分类 ≤ 0 时整块**仍然显示头部**，否则用户找不到创建入口；
- 拖拽落点只认分类行（`.cat-row`），类型行不接受落点。

### 4.8 实现阶段修正（与初版规划的差异）

以下四处在编码与验证过程中被推翻或补强，均为原型没暴露、只有写进真实界面才出现的问题：

| 位置 | 初版规划 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| 分类区首行 | 「全部」 | 「全部分类」 | 类型组已有「全部」（类型轴），两个「全部」并列时用户无法判断各自管什么 |
| 网格卡片的分类标记 | 封面右上角色点胶囊 + 分类名 | 元信息行的 5px 色点（`title` 带分类名） | 封面右上角被收藏星标占用：星标悬停才出现且 `position:absolute`，胶囊会与它重叠；底部又被页数/体积行占住。元信息行与列表视图同一套表达，反而更一致 |
| 选中态刷新 | 每次多选都 `renderLibrary()` | 只切 class + 刷新批量条（`syncSelection()`） | 整表 `innerHTML` 重建会把书列表滚动位置打回顶部，长书架下选第 8 份文档时列表会跳回顶部 |
| 空结果文案 | 两类（搜索无匹配 / 分类为空） | 三类：搜索无匹配、分类本身为空、分类非空但被类型筛掉 | 选了「论文 + MARKDOWN」得到空列表时提示「这个分类下还没有文档」是错的——分类里有文档，是组合条件筛掉了。第三类改为「没有匹配的文档 / 试试清除筛选条件」 |

另外在实现中补了两个防御：

- **`pruneSelection()`**：每次 `renderLibrary()` 丢弃指向已不存在文档的选中项，避免移除文档后批量操作带着幽灵 id。
- **`anyOverlayOpen()`**：Esc 清空选中前先判断是否有弹层打开，否则一次 Esc 会同时关掉命令面板并清空选中。

## 5. 边界与异常

| 场景 | 期望行为 |
| --- | --- |
| 旧版 `state.json`（无 `categories`） | 正常读取，分类区为空，「未分类」计数 = 全部文档 |
| 分类不存在（id 失效） | 该书的 `categoryId` 视为未分类参与筛选；不报错 |
| 删除分类时其中 0 份文档 | 直接删除，不弹二次确认（没有需要保护的东西） |
| 删除分类时有 N 份文档 | 二次确认写明 N；确认后文档落回未分类 |
| 名称全是空格 | 拒绝创建，提示「名称不能为空」 |
| 名称重复 | 拒绝，提示「已存在同名分类」 |
| 分类数已达 40 | `＋` 按钮禁用，`title` 说明原因 |
| 拖拽期间源文档被移除 | `assign_category` 找不到 id 时静默跳过（幂等），不整体失败 |
| 批量归类含已删除的书 | 同上，按存在的处理 |
| 写盘失败 | 命令返回错误串；前端 `toast` 并**重新拉取书架**，避免界面与磁盘不一致 |
| 分类下文档为空时点击 | 显示「这个分类下还没有文档」+ 一句引导（拖文档到这里） |
| 搜索词 + 分类同时生效 | 两轴 + 关键词三重 AND，`#gridHead` 显示组合态 |
| 双击分类行 | 第二次点击不重复触发编辑弹层（弹层已开时忽略） |

## 6. 验收标准

1. **编译与静态检查**：`cargo check`（`src-tauri/`）通过；`npx tsc --noEmit`（如有 TS 覆盖）、`npx oxlint src/js` 无新增告警。
2. **旧数据兼容**：手工构造不含 `categories` / `categoryId` 的 `state.json`，启动后书架正常、分类区显示「未分类 = N」。
3. **引导完整性**：创建 → 拖拽归类 → 筛选 → 批量归类 → 改名改色 → 删除，全链路可走通，每步都有可见反馈。
4. **引用完整性**：删除一个含 N 份文档的分类后，`state.json` 中不再有书指向该 id。
5. **零回归**：`grep` 确认 `visibleBooks` 在分类轴为 `null` 时行为与原实现逐字一致；原有 chips / 搜索 / 收藏测试全部通过。
6. **i18n**：切到 English 后分类区无中文残留，无 `key` 原样输出。
7. **视觉契约**：分类色点只用设计契约定义的颜色 token，不出现契约外 hex。
