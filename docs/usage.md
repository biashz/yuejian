# 阅笺用户手册

面向使用者的操作说明。开发与构建相关内容见 [README](../README.md)，产品与设计细节见 [产品功能规划](product-spec.md) 与 [设计契约](design-contract.md)。

## 1. 安装

安装包统一发布在 [GitHub Releases](https://github.com/biashz/yuejian/releases)，所有版本由 GitHub Actions 在三端分别构建。

| 平台 | 文件 | 安装方式 |
| --- | --- | --- |
| Windows | `YueJian.Reader_<版本>_x64-setup.exe` | 双击运行，按向导安装到当前用户目录 |
| macOS | `YueJian.Reader_<版本>_universal.dmg` | 打开 dmg，把「YueJian Reader」拖入「应用程序」 |
| Linux | `YueJian.Reader_<版本>_amd64.deb` | `sudo dpkg -i <文件名>.deb` |
| Linux | `YueJian.Reader_<版本>_amd64.AppImage` | `chmod +x <文件名>` 后直接运行 |

装好之后升级不必再手动下载安装包，见 [12. 更新](#12-更新)。

首次启动的注意事项：

- **macOS**：安装包未做 Apple 公证，系统可能提示“无法验证开发者”。在访达中右键点击应用选择「打开」，或执行
  `xattr -dr com.apple.quarantine "/Applications/YueJian Reader.app"` 后再启动。
- **Windows**：依赖系统 WebView2。Windows 11 已内置，Windows 10 若缺失需先安装 Microsoft Edge WebView2 Runtime。
- **Linux**：需要 WebKitGTK 4.1；AppImage 自带其余依赖，但不会解压到系统目录。

## 2. 界面速览

应用窗口分为六个固定区域：

| 区域 | 位置 | 作用 |
| --- | --- | --- |
| 标题栏 | 顶部 36px | 应用名、当前文档名、主题切换、界面语言、命令面板 |
| 图标栏 | 左侧 56px | 书架 / 阅读 / 搜索 / 设置，位置与顺序固定 |
| 书架面板 | 左侧 304px | 文档库、搜索框、类型筛选、分类区、批量归类条、导入入口（可折叠） |
| 主舞台 | 中间 | 书架视图或阅读视图 |
| 目录面板 | 右侧 268px | 按文档类型显示大纲 / 缩略图 / 信息 / 搜索，仅阅读时出现 |
| 状态栏 | 底部 26px | 当前文档、主题、页码与快捷键提示 |

## 3. 导入文档

支持两种方式，目标格式为 `.pdf`、`.md` / `.markdown`、电子书（`.epub` / `.fb2` / `.fb2.zip` / `.fbz` / `.cbz` / `.mobi` / `.azw3` / `.azw`），以及常见文本格式（`.txt` / `.log` / `.csv` 与代码、配置类扩展名，完整清单见「9. 阅读文本文件」）：

1. 点击书架面板右上角的 `+`，或底部「导入本地文档」按钮；
2. 直接把文件拖入窗口任意位置。

同一路径的文档只会入架一次（书架 id 由路径哈希生成），重复导入不会产生副本。

拖入的文件里如果有不支持的格式，会被静默跳过并在提示里报出跳过数量，不会中断整批导入。是否支持由 Rust 侧单一判定，前端不另维护白名单。

电子书里带 **DRM** 的（Adobe ADEPT、Kindle 等）在导入时照常入架，但打开会明确提示是哪一种方案——解密不是这里的活，换一份无版权保护的文件即可。漫画 `.cbz` 按固定版面整页显示，字号与页边距那几项对它不起作用。

## 4. 书架

- **搜索**：书架面板顶部输入框按书名与作者过滤，两字以上同时搜正文（见 4.2）；`Ctrl/Cmd + K` 打开的是全局命令面板。
- **筛选**：全部 / PDF / Markdown / 文本 / 收藏五档。
- **排序**：按最近打开时间倒序，不支持手动排序或收藏置顶。
- **进度**：每个条目下方显示阅读进度条。
- **收藏**：点击「全部文档」封面卡片右上角的星标切换，阅读视图文档栏也有同样的星标按钮。
- **移除**：点击条目右侧的删除按钮，仅从书架移除记录，不会删除磁盘上的原文件。

### 4.1 用分类整理书架

书架里可以自己建分类，把文档分门别类放好。一份文档同时只属于一个分类，没归类的一律在「未分类」里。

- **新建**：分类区右上角的 `＋`，填名称（最多 20 字）、选一个颜色，保存即可。同名分类会被拒绝。
- **归类**：
  - 直接把书架里的文档（列表行或封面卡片）拖到分类上；
  - 或按住 `Ctrl`（macOS 为 `Cmd`）逐份点击选中，在浮出的批量条里选「归类到…」；
  - 拖到「未分类」或批量选「未分类」，就是把文档移出分类。
- **筛选**：点分类即筛出该分类下的文档，再点一次取消。分类筛选和上方的 全部 / PDF / Markdown / 文本 / 收藏、以及搜索框可以叠加使用；区块标题会显示当前组合，右侧的「清除筛选」一次复位。
- **改名与配色**：鼠标移到分类行，点右侧 `⋯` 打开编辑弹层，可改名、换色。
- **删除**：编辑弹层左下角的「删除分类」。分类里的文档会变成「未分类」，文档本身不会被移除；分类为空时不会弹二次确认。
- **折叠**：点分类区标题可收起，收起后只留一行标题。
- **上限**：最多 40 个分类。

> 分类只存在于 `state.json`，不会写进你的 PDF / Markdown 文件，换设备时把 `data` 目录一起拷走即可。

### 4.2 搜索正文（跨书）

搜索框同时做两件事：按书名与作者过滤书架，以及在该范围内**搜每本书的正文**。输入两个字以上才会开始搜正文。

- **结果分两处**：书名匹配的排在书架上，正文命中的列在下方「全文命中」区——一本书书名没匹配上、正文里却有命中时，两处都会出现，不会互相盖住。
- **范围跟着筛选走**：上方选了 PDF 或某个分类，就只在这个范围里搜。
- **点一条命中**直接打开那本书并**落到那一处**：文本落到那一行、PDF 落到那一页、电子书落到那一章；关键词同时填进右侧栏搜索框，对应的那一条会高亮并滚进视野，可以顺着它继续看上下文。
- **Markdown 例外**：只把关键词填进侧栏搜索，不按行号跳。检索拿到的是源码行号，而渲染后的页面（表格、脚注、代码块）与源码行对不上，硬跳必然错位。
- **进度可见**：第一次搜某本 PDF 或电子书要先把正文抽出来（一份几百页的 PDF 大约几秒），主区会显示「正在建立索引 42% · 书名」。抽出来的索引留在 `data/search/`，同一本书再搜是瞬时的；文件的体积或修改时间变了会自动重建。
- **跳过的书**：带 DRM、文件已被删除、PDF 结构损坏的书会被跳过，抬头里会说明「几本未能参与检索」。漫画（CBZ）没有文字可搜，同样不在结果里。

> 索引只存正文与位置标签，不存排版，也不上传。删掉一本书时它的索引会一起删掉。

## 5. 阅读 PDF

打开 PDF 后进入阅读视图，正文为连续滚动的页面，可直接用鼠标选中并复制文字。

阅读视图顶部是文档栏：左侧「书架」按钮返回书架，中间显示标题与元信息，右侧依次为收藏、专注模式、目录面板开关。

PDF 的工具栏依次为：上一页 / 页码输入框 / 总页数 / 下一页 / 缩小 / 缩放比例（点开可切常用比例或「适合宽度」「适合页面」）/ 放大 / 放映 / 目录面板开关 / 分栏（两栏同文档时另有联动开关）。

打开时默认按**适合宽度**缩放：页宽撑满可视区，正文字号够大，页面超出屏幕的部分纵向滚动查看。想看整页排版就点缩放比例，切到「适合页面」；这两种适配模式都会跟着窗口和分栏宽度自动重算。

右侧目录面板有三个标签：

| 标签 | 说明 |
| --- | --- |
| 目录 | 读取 PDF 内置大纲，点击跳转章节 |
| 缩略图 | 按页预览，点击定位 |
| 搜索 | 全文关键词匹配，命中处高亮，回车跳转下一处 |

阅读位置（页码与滚动比例）会自动写入 `state.json`，下次打开自动恢复；缩放比例每次都从「适合宽度」重新计算，不沿用上次的手动调整。

## 6. 双栏对照

适合「同一篇论文看两处」或「两份文档对照读」。

- **拆分与合并**：阅读视图工具栏右侧的分栏按钮、`Ctrl/Cmd + \`，或用命令面板里的「分屏」；再次触发即合并。拆分时右栏默认打开当前这份文档，并与左栏停在同一位置。
- **活动栏**：两栏各自独立，翻页、缩放、目录与搜索只作用于活动栏。点一下某栏或在该栏内滚动，它就成为活动栏，工具栏页码、右侧目录与状态栏随之切换；两栏顶部各有栏头显示书名与页码。
- **换文档**：在活动栏里从书架选另一份文档，另一栏保持不变，因此可以一份 PDF 配一份笔记对照读。
- **联动**：两栏打开同一份文档时工具栏会出现联动按钮。开启后在一栏翻页或滚动，另一栏同步到同一段文字；对齐按「页码 + 页内相对比例」计算，两栏可视高度不同也不会错位。开关状态会被记住。
- **合并**：合并时保留活动栏的文档；若左栏是空的、只有右栏有文档，文档会接回左栏，不会出现合并后空白。
- **会话性**：分栏不写入设置，下次启动总是单栏。

## 7. 演示模式

把 PDF 铺满整块屏幕放映，适合投到第二块屏或做组会分享。

- **入口**：PDF 工具栏的放映按钮、`F5`，或命令面板里的「演示」。
- **翻页**：点右半屏前进、左半屏后退；滚轮向下翻下一页、向上翻上一页；键盘方向键、`PageUp` / `PageDown`、空格、回车、`Home` / `End` 同样可用。
- **切换顺滑**：进入时先把屏幕上已经画好的那页顶上去，等全屏过渡结束再补一次高清渲染，切换过程不会黑屏或闪白。
- **退出**：`Esc`、`F5`，或直接用系统快捷键退出全屏。退出后回到放映时停留的那一页，阅读位置与演示保持一致。
- **限制**：只有 PDF 能放映；在 Markdown 或文本文件上触发会提示不支持。

## 8. 阅读 Markdown

Markdown 在 Rust 侧渲染为安全 HTML 后再交给前端显示，支持 GitHub 风格语法：

- 工具栏为 `A−` / 当前字号 / `A+` / 行高切换 / 版心切换 / 目录面板开关；
- 表格、任务列表、引用、脚注、删除线、自动链接；
- 一至三级标题自动生成锚点与右侧目录，滚动时目录高亮当前章节；
- 代码块按语言高亮，行内代码使用等宽字体；
- 相对路径图片经 `asset` 协议转换为可访问地址，随文档所在目录解析。

正文使用宋体、标题使用楷体，行高 1.9 起，适合长时间阅读。

## 9. 阅读文本文件

`.txt`、`.log`、`.csv` 以及三十余种代码与配置扩展名（`.json`、`.yml`、`.toml`、`.rs`、`.ts`、`.js`、`.py`、`.go`、`.sql`、`.ini`、`.conf`、`.gitignore` 等）都能直接打开。语言按扩展名自动判定，界面上不做语法高亮，只保证「内容没丢、乱码没有」。

### 9.1 编码

这一节是文本阅读最容易踩坑的地方，值得单独说清楚。

应用不假定文件是 UTF-8，而是按三步判定编码：

1. **BOM**：文件开头有 `EF BB BF` / `FF FE` / `FE FF`，直接按对应编码解码，这是硬证据；
2. **探测**：没有 BOM 时，用 Firefox 同源的检测器读前 8KB 猜编码。中文 Windows 上记事本存的 `.txt` 多为 GBK，这一步能正确识别；
3. **解码**：按判定结果解码，个别无法映射的字节用替换字符（`�`）代替，不会整篇失败。

BOM 还会让「疑似二进制」的判断让路：UTF-16 正文里每个 ASCII 字符后面都跟着一个 `0x00`，若拿 NUL 字节当二进制证据，整类 UTF-16 文件都会被挡在门外。有 BOM 就按文本处理，这条优先级高于 NUL 检测。

因此中文记事本存的 GBK 文本、带 BOM 的 UTF-8 文本、老式 GB18030 文件都能正常打开。判定结果写在右侧「信息」面板里；判错了就在同一处换一个编码重开（见 9.2）。

> 早先版本用 `fs::read_to_string` 直接读，遇到 GBK 会整篇报错「stream did not contain valid UTF-8」——这是本次重做编码链的原因。

### 9.2 编码判错了怎么办

探测再准也有判错的时候：短文件、夹着少量中文的英文日志、日文与繁体中文混排的文本，都可能落到错误的编码上。这时去右侧「信息」面板，点「编码」这一行——它会展开一组常见编码，选一个就以该编码重新打开：

- 第一项是 **自动检测**，也就是默认行为；
- 后面按语种给出 UTF-8、GB18030（简体，含 GBK / GB2312）、Big5、Shift_JIS、EUC-KR、Windows-1252、UTF-16 小端 / 大端。

选过之后按钮上会标「手动」，这个选择会**记进书架**，下次打开同一份文件仍然按它解码，直到你在同一处改回「自动检测」。按钮上标的「自动 / 手动」就是为了让你一眼看出这份文件是被猜出来的还是自己指定过的。

指定编码时会跳过一切自动判定——包括「这看起来不是文本文件」的二进制检测。既然你说了它是什么，就不该再被启发式挡住。UTF-16 文件没有 BOM 时探测常常落空，用这一项指定即可。

### 9.3 三种视图

工具栏左侧是 `正文` / `等宽` / `表格` 三档，按扩展名自动选默认值：`.txt` 类走正文，代码与日志走等宽，`.csv` / `.tsv` 走表格。切换只改变显示方式，不动文件本身。

| 视图 | 排版 | 适合 |
| --- | --- | --- |
| 正文 | 宋体、限宽居中、行首不缩进，**空行分段** | 文章、说明、README |
| 等宽 | 等宽字体、逐行对齐、可开行号 | 代码、日志、配置文件 |
| 表格 | 按分隔符拆列，粘性表头与行号列 | CSV、TSV 等数据文件 |

- **行号**：只在等宽视图可用，粘在左侧不随横向滚动移动。表格自带行号列，不需要这个开关。
- **软换行**：长行折到下一行显示，否则横向滚动。两者互斥——一旦折行，行号就没法和行首对齐了，所以打开软换行会自动关掉行号。
- 视图选择只在本次会话内记住；换一份文档回到该文档的默认视图。

等宽视图刻意不用「一行一个元素」的方式渲染。一份 5MB 的日志有十几万行，那样会产生十几万个节点、卡上几秒；这里整篇只有**两个** `<pre>`（行号 + 正文），节点数与行数无关，再长的文件也不会越滚越卡。

切行号、切软换行都只改类名，不重建正文——所以切换是即时的，已经算好的高亮不会丢，滚动位置也不会跳。

### 9.4 表格视图

`.csv` 与 `.tsv` 打开就是表格，不必先切视图。

- **分隔符按内容判断，不看扩展名**：只在表头行里数引号外的逗号、制表符、分号，谁多算谁。`.tsv` 是制表符，欧洲的 CSV 常用分号，看内容比看扩展名准。判出来的分隔符写在右侧「信息」面板的「分隔符」一行。
- **按 RFC 4180 解析**：引号包裹的字段里可以有分隔符和换行，`""` 表示一个引号。所以 `"图版多,页边窄"` 是一列而不是两列。
- **表头与行号列都粘住**：纵向滚动时表头压在顶部，横向滚动时行号列压在左边，左上角那一格两个方向都压——长表滚到第 200 行仍知道每列是什么。
- **列数按表头补齐**：某行少几列就补空格子，空格子显示 `—`，一眼看出那里原本没有内容，而不是把后面的列错位往上顶。
- **上限 1200 行 × 60 列**：超出部分不渲染，信息面板写明「表格仅显示前 1200 行」。表格的虚拟滚动还没做，宁可**显式截断**也不悄悄丢数据。

### 9.5 语法高亮

代码与配置类文件按扩展名自动高亮，不认识的扩展名一律不作猜测——高亮猜错的干扰比不高亮大得多。

- **语言范围**：`rs` / `py` / `js` / `ts` / `go` / `java` / `kt` / `c` / `cpp` / `cs` / `php` / `rb` / `swift` / `m` / `lua` / `pl` / `r` / `sh` / `sql` / `graphql` / `vb` / `json` / `yml` / `toml` / `ini` / `xml` / `css` / `scss` / `less` / `diff` / `mk` 等，配色跟随主题。
- **打开不等高亮**：先出等宽纯文本，颜色在空闲时补上。200 KB 的代码要一百多毫秒才着色，同步做就是可见的一顿。
- **上限 200 KB**：超过这个体量直接给等宽纯文本，不尝试高亮（高亮后的标记量约为原文的 3.6 倍，再大打开就明显卡）。这不是静默降级——右侧「信息」面板的「高亮」一行会写明「关（文件超过 200 KB）」。
- **信息面板的「高亮」**：`开` / `关（文件超过 200 KB）` / `关（该语言不支持）` / `无（这类文件不高亮）` 四种，一眼看出着色为什么没生效。

### 9.6 大文件

超过 8MB 的文本不再整篇解码，改走**行索引 + 窗口渲染**：

- **打开时**：只读前 8KB 判编码，再扫一遍全文把每行的起始字节偏移记下来（行索引）。实测 22.8MB / 20 万行的日志建索引约 80ms，100MB 约 300ms。
- **阅读时**：画布高度 = 总行数 × 行高，只负责把滚动条撑到位；真正渲染的只有可视区那一千多行，滚到哪儿取哪儿。所以内存占用与文件大小基本无关，拖到底部也不卡。
- **限制**：大文件按等宽阅读，行号常显，**软换行与语法高亮关闭**。软换行会改变行高，滚动位置就算不准了；高亮要整篇解析，100MB 的日志根本算不完。右侧「信息」面板会写明这一点。
- **搜索**：大文件的搜索在后端做（按行窗口逐段扫），命中显示行号，点一下跳到那一行。前端只有一两千行，遍历 DOM 等于只搜了当前屏。
- **上限**：最多索引前 150 万行（浏览器对元素高度有上限，20px 行高下约 3000 万像素）。超出部分不索引，状态栏与信息面板会说明。
- **什么时候仍然截断**：UTF-16 编码（换行占两个字节，按字节切行会劈开字符）与行数过少的超大文件（压缩过的 JSON、超长单行）仍读前 8MB 并弹提示。这是**显式**降级，不是静默丢内容。

### 9.7 侧栏

文本类文档没有大纲和缩略图，侧栏只保留两个标签：

| 标签 | 说明 |
| --- | --- |
| 信息 | 类型、编码（可点开切换）、行数、字数、换行符（LF / CRLF）、大小、语法高亮是否生效；表格类多一行分隔符；被截断时额外标注 |
| 搜索 | 全文关键词匹配，命中处高亮 |

## 10. 阅读电子书

支持 `.epub`、`.fb2`、`.fb2.zip` / `.fbz`、`.cbz`、`.mobi`、`.azw3` / `.azw`。打开之后主舞台是分页排版，右侧栏按需显示目录、书签、搜索与信息。

### 10.1 翻页与定位

| 操作 | 作用 |
| --- | --- |
| 点击右半屏、`→` `↓` `PageDown` 空格、滚轮向下 | 下一页 |
| 点击左半屏、`←` `↑` `PageUp`、滚轮向上 | 上一页 |
| 拖动底部进度条 | 跳到任意位置（松手才跳，拖动过程不跳） |
| `Ctrl/Cmd + ←/→` | 上一章 / 下一章 |
| `Home` / `End` | 书首 / 书尾 |
| 点击目录项 | 跳到该章节 |

排版是流式重排的，所以位置按 **CFI** 记录而不是页码：改字号、拉窗口、关掉重开都不会丢。

### 10.2 单页 / 双页

工具栏中间的书本图标切换。窗口变窄（竖长）时分页器会自己降成单页，不会改动你的选择。固定版面的漫画没有这一档——左右页由书自己决定。

点书里的插图（漫画则是整页图）铺满窗口放大：滚轮缩放、双击复原、点一下或 `Esc` 关掉。图是按原尺寸解码后重画的，不是把章节再排一次版，所以看得清细节。

### 10.3 书签

`Ctrl/Cmd + M` 或工具栏书签按钮加 / 删当前页。右侧栏「书签」标签列出全部书签，点一下回到原处，行尾按钮删除。书签随书保存在 `state.json`，一本书上限 200 条。

### 10.4 划线

在正文里选中一段文字，浮出的小窗给五个颜色：琥珀、橄榄、靛青、梅红、墨灰。选一个，那段文字就带上颜色，右侧栏「划线」标签按时间倒序列出全部划线，点一条跳回原处，行尾 × 删除。点正文里已有的划线可以换色或删掉。

- 划线按 **CFI** 记录，换字号、换主题、改窗口大小都不跑位
- 画在正文之上的一层 SVG 上，不改动书里的排版，划一条不会让整章重排
- 随书保存在 `state.json`，一本书上限 500 条
- 固定版面的漫画没有字符流，划不了线（点图可以放大，见 10.2）

### 10.5 全书搜索

右侧栏「搜索」标签输入关键词，跨章匹配、按章分组，命中处高亮，点一下跳过去。篇幅大的书会边搜边报进度，随时可以停。固定版面的漫画没有可搜的文字，搜索会直接返回空。

### 10.6 脚注

点击正文里的注号，注文弹在注号附近的小窗里，不会把当前页顶走；点别处或翻页自动关掉。指向别处的普通书内链接照常跳转。

### 10.7 电子书版式

阅读工具栏最右边的「Aa」打开版式面板。它只在打开电子书时出现，**改动即时生效并自动保存**，没有「完成」按钮。

面板在宽窗口下会占住右侧 332px，把阅读区挤窄——因为调的就是正文的宽窄疏密，浮在文字上面盖住它，等于闭着眼睛调。窄窗口（< 1024px）自动变成抽屉，后面压一层遮罩，点遮罩或按 `Esc` 关掉。右侧的目录栏可以和它同开，各自独立。

#### 预设

| 预设 | 适合 |
| --- | --- |
| 舒适中文 | 长篇小说、散文：首行缩进 2 字、行高 1.85、版心 660px |
| 紧凑 | 信息密度优先：黑体、无缩进 + 段间距、版心 780px |
| 西文衬线 | 英文书与双语书：左对齐、开连字符、关标点挤压 |

点一下就整组回填。改了任何一项，预设高亮消失、右上角出现「自定义」——不会出现「标着紧凑、值却是别的」。

#### 文字

| 项 | 范围 | 说明 |
| --- | --- | --- |
| 字体 | 宋体 / 黑体 / 楷体 | 都带通用族名兜底，缺字体时不会掉成方框 |
| 字号 | 14–28 px，`A−` / `A+` 步进 | 到头时对应那个按钮灰掉 |
| 字间距 | −0.5–2 px | 中文自带字距，一般 0–1px 就够；加多了会失去整体感 |

#### 段落

| 项 | 说明 |
| --- | --- |
| 行高 | 1.3–2.4，默认 1.85 |
| 分段方式 | 无 / 首行缩进 / 段间距，**三选一** |
| 对齐 | 左对齐 / 两端 |

首行缩进与段间距是两种互斥的分段策略：同时开启会得到「既缩进又拉开」的重复节奏。选「段间距」时才出现段距滑杆（0–32px），并且只在两段之间加空隙，不会给首段凭空多出一段高度。切回「首行缩进」时，段距值还留着，下次切回来不用重调。

#### 页面

| 项 | 范围 | 落到哪里 |
| --- | --- | --- |
| 页边距 | 8–120 px | 分页器的 `margin`（内容到纸边的距离） |
| 版心宽度 | 480–1200 px | 分页器的 `max-inline-size`（纸的最大宽度） |
| 列间距 | 2–14% | 分页器的 `gap` |
| 双页 | 开 / 关 | 分页器的列数；窄窗口由分页器自己降成单页 |

宽窗口下版心宽度决定「每行多少字」，窄窗口下页边距更明显——两个都在的时候，谁更紧谁说了算，这是分页器自己的规则，不是两张互不相干的设置。

#### 细节

| 项 | 说明 |
| --- | --- |
| 连字符 | 西文断词。中文不受影响；开两端对齐的英文书建议开 |
| 标点挤压 | 中西文之间自动留缝、标点占半角、标点不落在行首。中文正文建议开 |
| 覆盖排版 | 让书里写死的字体、字号、行高、缩进一并让位给上面的设置 |
| 覆盖配色 | 字色与底色跟随应用主题，**默认开** |

「覆盖配色」默认开着是有原因的：夜读主题下不接管字色，书里写死的深色字就压在深色底上，几乎看不见。想看出出版方原本的配色（有些书用颜色区分人物对白），把它关掉即可——关掉之后字色与底色就归书自己管。

「覆盖排版」关闭时，书里用 `em` / `%` 写的正文会跟着你的设置走，用 `px` 写死的部分不受影响；开启后连那些也一起接管。

面板底部的「恢复默认」把这一整套（含双页）恢复到出厂状态，也就是「舒适中文」。

固定版面的书（漫画 `CBZ`、杂志型 `EPUB`）页的大小与排版由出版方定，面板会整块变灰并给出一句说明——值照存，换成回流的书就用得上。

### 10.8 打不开的时候

| 现象 | 原因与处理 |
| --- | --- |
| 提示**带 DRM 保护** | 书被加密了（Adobe ADEPT、Kindle 等）。解密不是这里做的事，换一份无版权保护的版本 |
| 提示**文件已损坏或不完整** | 下载中断，或者只是把 `.zip` 改名成了 `.epub` |
| 提示**不是能读的格式** | 扩展名与内容对不上，确认文件本身是不是电子书 |
| 提示**文件超过 512 MB** | 整本载入内存，超过这个体积会拖死进程 |
| 目录是空的 | 这本书没有 NAV / NCX 目录，用进度条或翻页即可 |
| 点注号跳了页而不是弹窗 | 那个链接指向的是别的章节，不是脚注 |

打不开的时候，工具栏只剩侧栏开关：这本书没有页可翻、没有位可插书签，翻页按钮摆着只会让人以为点得动。修好文件（换成无 DRM 的版本、重新下载）后重开即可。

### 10.9 导出摘录

右侧栏「划线」或「书签」标签里，计数行的右侧有两个按钮：**复制** 与 **导出**。两者给出同一份内容，只有去处不同——复制进剪贴板，导出存成 `.md` 文件（默认文件名 `书名-摘录.md`，保存框里可以改）。

导出的是一本书的**全部摘录**，不只是当前页签那一种：

```markdown
# 书名

作者：某某

12 条划线 · 3 个书签 · 导出于 2026-11-19 14:30

## 划线

> 划线的那段原文

—— 第三章 · 靛青

## 书签

- 第五章 · 11-19 14:31
```

几点约定：

- **顺序是加入时间**：先划的在前面。按书中位置排序要先解析 CFI，而「按划的先后读一遍」本身就符合笔记习惯。
- **颜色写在出处行上**：琥珀 / 橄榄 / 靛青 / 梅红 / 墨灰。导成纯文本后颜色没法保留，但颜色名能带上你当时的分类意图。
- **原文按引用块输出**：多行原文每行都带 `>`，行首若是 `#` 或 `-` 会加反斜杠转义，避免在 Obsidian / Typora 里被重新排成标题或列表。
- **没有章节名的划线**落到「正文」，不会留空。
- **没有摘录时不显示这两个按钮**：空列表上摆一个必然导出空文件的按钮，比不摆更误导。
- 文件是 UTF-8 无 BOM，编码不会在别的编辑器里出问题。

## 11. 阅读设置

点击图标栏的「设置」，或在命令面板中搜索「设置」打开设置面板，改动即时生效，无需确认或重启：

| 设置项 | 可选值 |
| --- | --- |
| 主题 | 纸白 / 夜读 / 护眼 |
| 正文字号 | 15 / 17 / 19 / 21 px |
| 行高 | 紧凑 1.7 / 标准 1.9 / 宽松 2.1 |
| 版心宽度 | 窄 620 / 标准 720 / 宽 820 px |
| 打开文档时显示目录 | 开 / 关 |
| 专注模式 | 隐藏图标栏、书架面板与状态栏 |
| 启动时自动检查更新 | 开 / 关 |
| 界面语言 | 简体中文 / English |

电子书的版式**不在这里**——它有自己的面板（阅读工具栏的「Aa」），见 [10.7 电子书版式](#107-电子书版式)。分开的理由很实际：这一页是装完机调一次的，版式是看书时反复调的。

「恢复默认」把以上设置重置为纸白、17px、1.9 行高、720 版心，电子书版式也一并回到「舒适中文」预设。

面板高度跟着窗口走。窗口矮、设置项一屏放不下时，中间那一段自己滚，底部的「恢复默认 / 完成」始终留在屏幕里——不用滚到底去找按钮，也不会出现面板比窗口还高、内容掉到窗口外够不着的情况。

## 12. 更新

升级不需要重新下载安装包，应用内即可完成。

- **自动检查**：启动约 3 秒后静默检查最新发布。发现新版本会在后台下载，图标栏的「设置」角上出现一个朱红圆点。
- **手动检查**：设置 → 更新 → 「检查更新」，随时查看当前版本、最新版本与下载进度；「启动时自动检查更新」可关闭启动检查。
- **安装提示**：下载完成后，右下角浮出一张「新版本 vX.Y.Z 已下载」的卡片，上面有两个按钮。「立即安装」才会关闭阅笺并交给安装程序；「稍后再说」只收起卡片。这张卡片不是模态弹窗——不铺遮罩、不抢焦点、不拦键盘，弹出时你正在读的页面、翻页与快捷键都不受影响；收起后随时可以在设置 → 更新里再装。
- **安装**：点「立即安装」后应用退出并启动安装程序。安装程序严格分两步走：**先检查有没有旧版本**，有的话把旧的**卸载完整**（静默卸载 → 清掉卸载程序剩下的文件、快捷方式与「设置 → 应用」里的安装记录 → 确认主程序已消失），**然后**才开始写新版本文件。所以不会出现新旧文件混装，也不会出现两条重复的安装记录。
- **进度里看得见**：安装进度会分别标出「阶段 1/2：…卸载旧版本」与「阶段 2/2：开始写入新版本 vX.Y.Z」，卡在哪一步一目了然。卸载过程不会另外弹出第二个卸载向导。
- **旧卸载程序丢了也能升**：如果旧版本的 `uninstall.exe` 已被手工删除或被安全软件清掉，安装程序不会跳过检查，而是改为直接清理残留的主程序、快捷方式和安装记录，再进入安装。
- **数据保留**：升级中的卸载一律是静默卸载，`data/` 一定会保留，书架、设置与阅读进度都不受影响。只有从「设置 → 应用」手动卸载时，才会在确认页里问你「是否删除应用数据」。
- **macOS / Linux**：不会自动下载，按钮变为「去下载页」，用系统浏览器打开发布页下载对应的 dmg / deb / AppImage。
- **下载走系统代理**：应用内下载在 Windows 上会读取「设置 → 网络和 Internet → 代理」里的系统代理（也认 `HTTPS_PROXY` 环境变量），因此和浏览器使用同一条网络路径。若 45 秒内没有任何数据到达，界面会提示下载没有响应并放出「查看更新说明」，可改从发布页手动下载。

## 14. 数据位置与迁移

发布版的全部数据位于可执行文件同级的 `data/` 目录：

```
data/
├── state.json      # 书架、阅读进度与设置
└── webview2/       # 系统 WebView 的用户数据目录（Windows 下即 WebView2）
```

- Linux AppImage 的数据写在 `.AppImage` 文件同级目录的 `data/`；
- 调试构建使用项目根目录的 `.data/`；
- 不向 `%APPDATA%`、`~/Library` 或其他系统目录写入任何内容。

**迁移**：关闭应用后复制整个程序目录（或 AppImage 与同级的 `data/`），在新位置启动即可保留书架与进度。**备份**：只需备份 `state.json`。

## 15. 常见问题

**打开文档后书架空白 / 提示找不到文件**
书架只保存文件路径，不复制原文件。原文件被移动、重命名或所在磁盘未挂载时会打不开，重新导入新路径即可。

**阅读进度没有恢复**
进度在滚动与翻页后延迟写入磁盘，若在写入前强制结束进程可能丢失最后一次位置。正常关闭窗口不会丢失。

**PDF 页面空白或显示不全**
先确认文件本身未损坏（可用其他阅读器打开）；加密或仅有扫描图的 PDF 仍可显示图像，但文本层为空，无法选中复制与全文搜索。

**大文件卡顿**
PDF 按可视区域懒加载，但单页含大量高分辨率图像时仍会占用较多内存。可先缩小缩放比例以降低渲染尺寸。

**界面字体与预期不同**
标题使用楷体、正文使用宋体，均取自系统字体。系统缺少对应字体会回退到衬线字体，不影响功能。

**升级后书架和进度还在吗**
在。安装程序卸载旧版本时「删除应用数据」默认不勾选，`data/` 会原样保留；只有手动勾选才会清空。

**应用内更新一直没进度，但浏览器能下载**
两者走的网络路径不同：浏览器与应用内页面走系统代理，而下载安装包用的是系统自带的 `curl`，它只认 `HTTPS_PROXY` 环境变量。0.1.19 起已自动读取 Windows 系统代理；若仍卡住，说明是代理软件没把 `curl` 纳入（部分工具只代理浏览器），或安全软件拦截了下载进程。此时界面会给出 curl 的具体失败原因，按提示配置代理，或直接到发布页手动下载安装包。

**如何卸载**
Windows 在「设置 → 应用」中卸载，macOS 删除应用，Linux 卸载 deb 包。卸载不会自动删除 `data/`，确认不需要阅读记录后可手动删除该目录。
