# 电子书版式与设置面板 · 调研

> 目标：把「电子书阅读时的正文长什么样」从现在的 5 个开关，重做成一套**能认真调版式**的
> 面板（独立于通用设置），并且让调出来的东西在真书里真的生效。
>
> 现状基线：v0.1.37。`settings` 里电子书相关只有 6 个字段
> （`ebookFontSize` / `ebookLineHeight` / `ebookMargin` / `ebookFamily` / `ebookAlign` /
> `ebookOverride`），全部塞在通用设置抽屉的「电子书」一组里，注入路径只有
> `buildEbookStyles()` 一段 CSS 字符串。
>
> 本文只做调研与结论，不做取舍定稿——取舍在 `docs/ebook-layout-plan.md`。

---

## 1. 现有实现的可调面到底有多大

要判断「哪些能加」，先得数清楚现在手上有几个旋钮。分页器（`src/vendor/foliate/paginator.js`）
对外暴露的属性是封闭的一小组：

```js
static observedAttributes = ['flow', 'gap', 'margin', 'max-inline-size', 'max-block-size', 'max-column-count']
```

`attributeChangedCallback` 里它们分别落到 `#top` 元素的四个 CSS 变量上：

| 属性 | 落到的变量 | 默认值 | 是否触发重排 |
| --- | --- | --- | --- |
| `flow` | `--_flow`（`paginated` / `scrolled`） | paginated | 是（改 `#view` 结构） |
| `gap` | `--_gap` | `7%` | 否，纯 CSS |
| `margin` | `--_margin` | `48px` | 否，纯 CSS |
| `max-inline-size` | `--_max-inline-size` | `720px` | **是**（`render()`） |
| `max-block-size` | `--_max-block-size` | `1440px` | 否 |
| `max-column-count` | `--_max-column-count` / `--_max-column-count-portrait` | `2` / `1` | 否 |

**这六个属性就是分页器「愿意跟你谈」的全部。** 字号、行高、字体、对齐、缩进、段距、字距、
连字符、标点挤压……一个都不在里面，只能走另一条路：注入样式表。

注入的口子在 `afterLoad`——分页器每加载一个章节文档，就往 `doc.head` **末尾追加**一个空的
`<style>`，专门留给调用方写覆盖规则。它排在书自己所有样式之后，同权重下后者胜出。
这个口子叫 `setStyles(styles)`（`paginator.js:1100`），是目前唯一能改到章节文档内部的通道。

一个必须知道的副作用：分页器加载文档后会自己洗一遍 CSS——
把 `-epub-` 前缀悉数剥掉、`vw`/`vh` 换算成 px、`page-break-*` 改名成 `column-break-*`。
所以注入的规则里**不要指望 `-epub-` 前缀能生效**，也**不要用 `vh`**（会被换算成落笔那一刻的
视口高度，窗口一改就不对了）。

| 想调的东西 | 现有路径 | 结论 |
| --- | --- | --- |
| 字号 / 行高 / 字体 / 对齐 | 注入 CSS（`buildEbookStyles`） | ✅ 已有，可扩 |
| 页边距 | `Paginator.margin` 属性 | ✅ 已有，可扩到四边不等 |
| 首行缩进 / 段间距 / 字间距 | — | 缺口，注入 CSS 可补 |
| 连字符 / 标点挤压 / 孤行控制 | — | 缺口，注入 CSS 可补 |
| 列宽上限 / 列间距 / 最大列数 | `max-inline-size` / `gap` / `max-column-count` | 分页器原生支持，但前端还没接 |
| 竖排 | `writing-mode` 注入 | 缺口，能力上可行但风险高（见 §3） |
| 双侧对齐时的「疏排」控制 | `text-justify` / `font-feature-settings:"palt"` | 缺口 |

## 2. Chromium 到底支持哪些排版属性

WebView2 是 Chromium（真机 `Edg/157.0.0.0`），所以「能不能做」这个问题可以直接问浏览器。
用 `CSS.supports()` 逐条实测（`.playground/probe-css.mjs`，跑在真实应用窗口里）：

| 属性 | 结果 | 用途 |
| --- | --- | --- |
| `hyphens: auto` | ✅ | 西文断词 |
| `line-break: strict` | ✅ | 中文标点的严格换行规则 |
| `text-autospace` | ✅ | 中西文之间自动加间隙 |
| `text-align: justify` | ✅ | 两端对齐 |
| `text-align-last: auto` | ✅ | 段末行不强行撑满 |
| `text-indent: 2em` | ✅ | 首行缩进 |
| `text-justify: inter-character` | ✅ | 按字距而非词距分散 |
| `writing-mode: vertical-rl` | ✅ | 竖排 |
| `font-variant-east-asian: jis78` | ✅ | 旧字形 |
| `font-feature-settings: "palt"` | ✅ | 标点半角挤压 |
| `text-wrap: pretty` | ✅ | 减少孤行 |
| `orphans` / `widows` | ✅ | 孤行控制 |
| `break-inside: avoid` | ✅ | 段落不跨页 |
| `column-span: all` | ✅ | 跨栏标题 |
| `ruby-position: over` | ✅ | 注音 |
| `text-emphasis` | ✅ | 着重号 |
| **`hanging-punctuation: allow-end`** | ❌ | **悬挂标点不支持** |

这一条 ❌ 是唯一的技术缺口，而且正好是中文排版里最想要的那个（Legado、Koodo 都有
「悬挂标点」开关）。它没有替代品：悬挂标点的语义是「让句末标点溢出到版心之外」，
CSS 里没有第二种写法能做到。

可行的近似方案是**标点挤压**而不是悬挂：
`text-justify: inter-character` + `font-feature-settings: "palt"` + `line-break: strict`
三条一起，能让标点在行内占半角、行末不出现「。」单独一行。视觉上靠近悬挂标点的效果，
但原理不同（一个是压缩行内空间，一个是允许溢出边界）。这一点要在文档里说清楚，
不能叫「悬挂标点」骗用户。

`text-autospace` 值得单独提一句：它是 Chromium 独有的（Safari / Firefox 都没有），
而我们只跑 WebView2，所以可以放心用。开了之后「中文 English 混排」不再需要手工打空格。

## 3. 竞品是怎么摆这些旋钮的

查了六家。挑的都是「用户会拿它跟阅笺比」的那一类。

### 3.1 Thorium Reader（EDRLab，桌面端，最像我们）

两组设置，藏在 Display 面板里：

- **Layout**：分页 / 滚动、对齐（auto | justify）、列数（auto | 1 | 2）
- **Customize text formatting**（打开后才出现下面两栏）：
  - *Text*：字号、字体族（Serif / Sans / Humanist / Modern / Old Style / OpenDyslexic /
    monospace / duospace）
  - *Spacing*：margin / paragraphs / lines / words / letters 五档

最值得抄的不是这些项，是它的**持久化模型**：设置**按书保存**，并且可以
Save（存成命名配置）/ Apply（把当前配置套到别的书上）/ Reset（回到该书默认）。
FXL 与 PDF 只有缩放和单双页，其余全灰。

> 启示：`Spacing` 里 margin 和 paragraphs 分成两项（一个是版心边距，一个是段间距），
> 这个区分中文阅读器普遍做得差——它们常常只有「段间距」没有「版心边距」。

### 3.2 Apple Books

- 主题预设：Original / Quiet / Bold / Paper
- 字号 A- / A+
- 字体
- Bold Text 开关
- **Customize** 展开后：Line spacing / Character spacing / Word spacing 三条滑杆 + Margins +
  **Justify Text 开关** + **Allow Multiple Columns 开关**
- Reset Theme
- PDF 与 FXL 走另一套 Appearance（只有 Vertical Scrolling）

> 启示：「Justify」是**开关**而不是二选一的分段控件——因为左对齐是"关"，两端对齐是"开"，
> 用户心里只有一个布尔。我们用「左对齐 | 两端对齐」两个按钮表达的是同一件事，
> 但多占了一倍宽度，还暗示存在第三种状态。

### 3.3 Kindle

- Font 页：字体（含 **Publisher Font** 选项，书里嵌了字体才出现）、字号滑杆、粗细（5 级）
- Page 页：行间距、页边距、竖屏/横屏、对齐（两端对齐 / 左对齐）
- Theme 页：把当前 Font + Page + Reading 的组合存成命名主题、重命名、删除
- 全局生效，**不按书**；COMIC 另走分格视图

> 启示：「Publisher Font」这种**让位给书自己的选择**，比一个粗暴的「强制覆盖」开关更细腻。
> 我们的 `ebookOverride` 现在是一刀切：开了就全部覆盖（含配色）。可以拆成
> 「字体 / 字号 / 间距 / 配色」四件分别让位——但这是加分项，不是本轮必须。

### 3.4 小幻阅读（richasy，Windows 原生，中文）

三组：

- **字体**：系统字体选择 / 字重 100–900 / 字间距 / 覆盖字体
- **排版**：行高 / 段间距 / 首行缩进 / 两端对齐 / 连字符 / 覆盖布局
- **页面**：最大列宽 / 列间距 / 垂直边距 / 水平边距
- 主题：跟随系统 / 白纸 / 羊皮纸 / 护眼绿 / 夜间 / 自定义 + 自适应颜色
- 布局模式：分页 / 滚动 / 文档，最大列数 1–4

> 启示：这是**最接近我们处境**的一家（Windows、WebView、中文正文）。它的「页面」组
> 正好对应分页器那三个还没接的属性（`max-inline-size` / `gap` / `margin`）。
> 「覆盖 X」做成逐项开关而不是一个总开关，也是它和小幻共同的做法。

### 3.5 Koodo Reader（Web 技术栈，开源）

- 主题成对出现（背景 + 文字），亮度滑杆，反色
- 行高 1 / 1.25 / 1.5 / 1.75 / 2（五档预设，不是滑杆）
- 段间距：0–120 滑杆 + 1–5 倍率两套表达
- 对齐：左 / 右 / 两端
- 首行缩进 / 连字符 / 孤行控制：三个独立开关
- 竖排、简繁转换
- **六套版式预设**：推荐版式 / 赫蹏 / 漢字標準格式 / typo / Tufte / Typebase
- 三个覆盖开关：链接样式 / 文本样式 / 背景样式

> 启示：「版式预设」这个抽象很有价值——它把一个六七个维度的组合压成一次点击。
> 但六套预设对我们是过度设计；**三套**（舒适中文 / 紧凑 / 西文衬线）足够覆盖 90% 的场景，
> 而且预设本身就是「默认值」的自然延伸。

### 3.6 Legado（Android，中文网文第一梯队）

- 字体、字重（‑1 ~ 2）、字间距、行间距（建议 8–12）、段落缩进（0 / 2）、段落间距、
  标题位置、两端对齐
- **悬挂标点**、**标点压缩**（两个独立开关）
- 可保存多套风格，每本书可单独套用

> 启示：中文阅读器把「标点压缩」和「悬挂标点」当两个独立开关，是因为它们解决的
> 是两个不同的问题。我们只能做前者（§2 的 ❌），那就老老实实只做一个开关，命名为
> 「标点挤压」。

**三个明确的空白**（六家至少四家有、我们一个都没有）：
首行缩进、段间距、字间距。这三个恰好也是中文正文最影响观感的三个。

## 4. 中文正文的取值区间

调研里捡到的、可以当默认值和滑杆范围的数字：

| 参数 | 常见区间 | 说明 |
| --- | --- | --- |
| 正文字号 | 14–17px（屏幕）/ 18–21px（沉浸阅读） | 越小越适合年轻/资讯读者，越大越适合长文与年长读者 |
| 行高 | 1.5–1.8 倍 | 段落越长取值越靠上；低于 1.4 挤，高于 2 散 |
| 行高绝对值 | 字号 13 时 20–24px；16 时 24–29px | 与「1.5–1.8 倍」互为校验 |
| 段间距 | 10–16px，或「比行高大 5–8px」 | **手机端常用段间距代替首行缩进** |
| 首行缩进 | 0 或 2em（2 字符） | 中文书籍传统；网络阅读普遍改为不缩进 + 段间距 |
| 字间距 | 0–1.5px，常用 0.5–1px | 中文自带字距，密排长文可加，加多了失去整体感 |
| 版心两侧留白 | 8–16px（窄屏）/ 48–120px（宽屏） | 宽屏下由 `max-inline-size` 控制列宽，比压 margin 更合理 |
| 正文色 | 不用纯黑，`#3f3f3f` / `#333` / `#595959` | 纯黑在屏幕上偏硬 |

两条与「中文电子书」直接相关的判断：

1. **首行缩进和段间距是互斥的两种分段策略**，同时开会显得段落既缩进又拉开、节奏重复。
   多数中文阅读器不做互斥约束，用户开两个就得到一个奇怪的版式。面板里应该做成
   「二选一 + 允许都不选」，而不是两个独立滑杆。
2. **`text-align: justify` 在中文里是安全的，在西文里不是**。中文每字等宽，两端对齐不会
   出现「一行里词距被拉得很开」的丑陋现象；西文会。所以对齐的默认值应该跟着书的主语言走
   （或者跟着字体族走：选 serif/西文衬线时默认左对齐）。

## 5. 十条结论

1. **设置面板必须独立。** 现在它挤在通用设置抽屉的末尾，和主题、语言、更新检查混在一起。
   版式设置是「看书时反复调」的高频动作，通用设置是「装完调一次」的低频动作，
   混在一起等于每次都要滚过一半无关内容。
2. **能接分页器原生属性的，优先接原生。** `max-inline-size` / `gap` / `max-column-count`
   是分页器自己算的，走属性比注入 CSS 稳（注入 `max-width` 会和分页器的分栏计算打架）。
   只有原生不覆盖的（字号、行高、缩进、间距、连字符、对齐细节）才注入 CSS。
3. **首行缩进与段间距做成互斥选择**，不是两个滑杆。默认给「段间距」，因为屏幕阅读的主流
   是段间距。
4. **标点挤压可以做，悬挂标点不能做。** 只能命名前者。文档和 UI 里都不能写「悬挂标点」。
5. **`ebookOverride` 必须拆开。** 至少拆成「排版覆盖」与「配色覆盖」两个开关。
   前者管字体/字号/行高/间距，后者管字色/底色。颜色那半还要多一个「跟随主题」的语义。
6. **加版式预设，但只加三套。** 预设是「默认值」的自然延伸：用户改了任何一项就变成
   「自定义」，点预设就整组回到某一套。三套：舒适中文（缩进 + 段间距 0 + 行高 1.8）、
   紧凑（无缩进 + 小段距 + 行高 1.65）、西文衬线（左对齐 + 连字符开 + 大行高）。
7. **列数控制值得加。** 分页器原生支持，成本只是三个属性赋值。但只在宽窗口下有意义，
   窄窗口要自动降为 1 列（分页器已有 `--_max-column-count-portrait` 逻辑）。
8. **竖排不做。** 能力上可行（`writing-mode: vertical-rl` 支持），但分页器的分栏方向、
   翻页手势、CFI 定位全是横向假设，改一个属性会得到一本错版的书。明确列为「不做」，
   不要留半成品。
9. **简繁转换不做。** 需要一份完整对照表和词组级歧义处理，成本远超收益。
10. **持久化仍走全局 `settings` 的平铺字段，组织方式在代码里收。**
    Rust 侧 `Settings` 是强类型 struct + 容器级 `serde(default)`，加平铺字段零成本；
    但把它改成嵌套对象会让旧 `state.json` 里的 `ebookFontSize` 等键被 serde 静默丢弃
    （默认忽略未知字段），等于升级就丢设置。所以**存储保持平铺追加**，
    在前端建一个 `ebook-layout.js` 作为「版式视图对象」：读写都过它，
    面板/样式/预设三方只跟它打交道。将来加「按书覆盖」时，多存一份
    `bookId → 若干平铺字段的差量`，仍然不用动既有键。

## 6. 风险

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 注入 CSS 与书自带样式打架 | 有些书用 `!important` 钉死字号 | 已由 `ebookOverride` 的 `!important` 分支兜住；开关命名要让人能理解这层含义 |
| `text-autospace` 是 Chromium 独有 | 将来换内核对齐行为会变 | 只当增强，不当依赖；不放进预设的核心组合 |
