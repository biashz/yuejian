# 打印与导出当前文档 — 功能规划

> 对应 [product-spec.md](product-spec.md) 功能地图 P2 的最后一项「打印 / 导出当前文档」。摘录导出管的是笔记（见 [feature-export.md](feature-export.md)），这一项管的是**正文**。

## 1. 定位

读完之后最常见的两件事：把这份文档**印出来**，或者**换个地方继续看**（发给别人、归档、在没有装这个应用的机器上打开）。

这两件事在四种格式上并不对称，所以这一期不给「万能导出」，只做两个诚实出口：

| 格式 | 打印 | 导出为 HTML | 另存原文件 |
| --- | --- | --- | --- |
| Markdown | ✓ | ✓ | ✓ |
| 文本 / 代码 / CSV | ✓ | ✓ | ✓ |
| PDF | — | — | ✓ |
| 电子书（EPUB / FB2 / MOBI / CBZ …） | — | — | ✓ |
| 超大文本（窗口渲染） | — | — | ✓ |

## 2. 为什么 PDF / 电子书只交副本

PDF 的版面是文件里写死的（对象坐标、嵌入字体、裁剪框），电子书的排版由它自己的 CSS 与阅读器共同决定。前端**再渲染一遍**只会得到一份更差的近似品：图丢了、字体换了、分页全乱，而用户并不知道自己手里这份是劣化的。

「把这本书带出去」需要的正是原样的字节，`fs::copy` 就够了。要打印 PDF，用系统阅读器打开副本——那才是对这份格式最合适的工具。

**这也解释了为什么不做「导出为 PDF」**：应用里没有 PDF 生成器，靠 `window.print()` 的「另存为 PDF」只能覆盖文本类文档，却会在 UI 上暗示「所有文档都能变 PDF」，那个承诺兑现不了。

## 3. 打印：舞台 + 平台分流

### 3.1 为什么不能就地打印

阅读区是 `overflow: auto` 的滚动容器。纸张没有「视口」，直接打印只会得到当前看得见的那一屏；工具栏、侧栏、文档栏在纸上全是噪音。

做法是四步：**克隆正文 → 塞进 `#printStage` → 给 `<body>` 打上 `is-printing` → 走系统打印**。`@media print` 里只留舞台：

```css
body.is-printing > *:not(#printStage) { display: none !important; }
```

### 3.2 三个必须处理的细节

1. **舞台在屏幕上必须不存在**。`#printStage { display: none }` 是常态，只有打印媒体里才 `display: block`。冒烟直接断言打印后 `getComputedStyle(stage).display === "none"`——否则用户会在阅读区里看见一份重复的正文。
2. **进场动画会把内容推下去**。`.md-doc` 带 `rise 600ms both`，类名一挂上动画就开始跑；打印若抓在动画中途，版式整体错位。舞台里一律 `animation: none !important`。
3. **打印对话框是异步的**。命令返回时纸还没出，此刻清空舞台会打出白纸。收摊交给 `afterprint`（`clearPrintStage`）；事件不来也无害——`is-printing` 只对纸张媒体生效，屏幕上什么都看不见。

`is-printing` 这个开关而不是无条件生效，是有意的：用户若绕过菜单直接按浏览器默认打印，至少还能打出界面，不会得到一张白纸。

### 3.3 平台分流放在 Rust

| 平台 | 通路 | 原因 |
| --- | --- | --- |
| macOS | wry `WebviewWindow::print()` | WKWebView **不支持** `window.print()`，调用后静默无反应，连错误都没有 |
| Windows / Linux | `window.print()`（由 Rust `eval`） | 反过来：wry 的 `print()` 只有 macOS 实现；WebView2 的 `PrintAsync`、WebKitGTK 的打印对话框都挂在 `window.print()` 上 |

Tauri 自己的文档就写着「Currently only supported on macOS on `wry`. `window.print()` works on all platforms.」——两边各缺一半。判断放 Rust（`print_webview` 里按 `cfg(target_os)` 分），前端只发一个命令：平台判断散进界面代码，是这类缺陷最常见的来源。

两边都遵守 `@media print`，所以「只打印正文」这件事完全交给 CSS，命令里不拼任何内容。

## 4. 导出 HTML：取屏幕上的排版，不重跑解析

正文的 HTML 直接**克隆 `pane.mdDoc`**，而不是再调一次 `comrak` / 文本渲染器。

理由不是省事：屏幕上的排版里含着用户的选择——等宽视图还是正文视图、行号开没开、软换行、表格视图、代码高亮的着色。另起一条渲染管线意味着同一个文件在应用里和导出的文件里排版不一致，而这种不一致只在用户打开文件时才会被发现。克隆带上容器类名（`md-doc is-text text-code show-gutter`），导出的 CSS 按同一套类名还原。

克隆体只清三样东西：

| 清掉 | 为什么 |
| --- | --- |
| `loading="lazy"` | 离开应用后没有任何东西会触发加载，图片会永远是空白 |
| `is-broken` | 应用内「这张图没读出来」的标记，不是文档内容 |
| `is-focus` / `is-active` / `is-hit` | 描述「刚才点过哪儿」，不是文档内容 |

### 4.1 图片必须内联

应用内的图片是 `asset://` 地址，**只有本应用认**。不内联，导出文件在别的机器上就是一排碎图标。

- 路径从 `img.dataset.src` 拿：渲染时 `rewriteImages` 会把原样的相对路径记在 `data-src` 上（`src` 已被改写成 asset 地址）。改写时顺手记下，比事后反解 URL 可靠。
- 解析用 `reader-md.js` 的 `resolvePath()`，与显示时同一套规则，不重复实现一遍路径归一化。
- 编码成 data URL 在后端做（`read_image_data_url`）：单张上限 8 MB，超出就让这一张失败。
- **单张失败不中断整份导出**：一张图丢了比整个文件导不出来好，失败的图保留 `alt`；提示里明说「N 张图片未能内联」，不静默。

## 5. 菜单：一个入口，按格式取舍

工具栏最右端一个「⋯」，下拉出「打印 / 导出为 HTML / 另存原文件」。

- 不钉三个按钮：这三件事都是偶尔用一次，钉上去会挤掉每天都在用的翻页与缩放；而且「哪个格式能用」需要一行说明，按钮放不下。
- **能力判定集中在 `docCapabilities()`**，菜单只管「有什么画什么」。判定散进模板，同一条规则就会出现两处，迟早对不上。
- **缺项要写原因**：PDF / 电子书下方明说「按原格式另存；要打印请用系统阅读器打开副本」，大文件下方明说「只加载了当前窗口」。少一项却不解释，用户只会以为功能坏了。
- `Ctrl/Cmd + P` 走同一条路径。只放在「阅读视图」判断之后——在书架页按 Ctrl+P 不该把书架界面打印机出来。

## 6. 模块划分

| 文件 | 职责 | 边界 |
| --- | --- | --- |
| `src/js/reader/doc-export.js` | 能力判定、取快照、图片内联、拼 HTML、导出、另存副本 | 不自己找活动栏，`pane` 由调用方传入 |
| `src/js/reader/doc-print.js` | 打印舞台的填充与收摊 | 不发命令以外的请求 |
| `src/js/reader/doc-menu.js` | 菜单片段与展开状态 | 只拼字符串，不绑事件 |
| `src-tauri/src/commands.rs` | `save_text_file`（加 `ext`）、`save_file_copy`、`read_image_data_url`、`print_webview`、`base64` | 不掺和格式 |

`doc-export.js` **不 import `panes.js`**：工具栏与 `panes.js` 本来就有双向依赖（`panes` → `toolbar` → `doc-export`），再加一条就成环。改成 `pane` 由调用方传入后，依赖是单向的，顺带也让这个模块在冒烟里不依赖界面状态。

`base64` 手写而不是引 crate：规则只有一张 64 字符表和三条移位，二十行写完；引一个依赖要多付一份版本、许可证与打包体积的账。Rust 单测覆盖三种补位长度。

## 7. 边界

- **不做**：导出为 PDF / docx、批量导出、导出选中段落、打印页码与页眉。
- **不做**：PDF 逐页截图导出、电子书转 Markdown。都属于「转格式」，与「原样交出去」是两件事，且都要求先解决排版引擎。
- **分栏时导出活动栏**：菜单在哪个栏的工具栏上点，就导出哪一栏，与侧栏、工具栏同一口径。
- **大文件锁死**：`windowed` 的文档只渲染一个窗口，整篇导出必然缺内容，因此只留「另存原文件」。

## 8. 验收

| 项 | 标准 |
| --- | --- |
| 菜单 | Markdown 出「打印 / 导出 HTML / 另存副本」，无多余说明 |
| HTML | `<!DOCTYPE html>` 开头、含 `<title>`、含「导出于」、正文取自当前 DOM |
| 图片 | 本地图内联成 `data:` URL，导出里不残留 `asset.`；读不到的图不带进文件 |
| 路径 | 图片按文档目录解析成绝对路径（`C:\fixtures\pic.png`） |
| 打印 | 舞台有正文、屏上 `display: none`、`body.is-printing` 为真、菜单自动收起 |
| 收摊 | `afterprint` 后类名摘掉、舞台清空 |
| 快捷键 | `Ctrl+P` 与菜单走同一条路径 |
| PDF | 只有「另存原文件」，且有一行说明；副本命令拿到原路径与同名目标 |
| 大文件 | 只有「另存原文件」，说明「只加载了当前窗口」 |
