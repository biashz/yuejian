# 摘录导出 — 功能规划

> 对应 [product-spec.md](product-spec.md) 功能地图 P2「摘录导出」。把一本书的划线、书签汇成一份 Markdown，交给笔记软件继续用。

## 1. 定位

阅笺不做账号、不做云同步，笔记就只能留在本机。导出是这些笔记**离开应用的唯一通道**：用户在别的软件里继续加工，而不是被锁在一个只有阅读功能的窗口里。

因此这一期只做一件事——**把已有的摘录原样交出去**，不新增编辑能力，也不做模板市场。

## 2. 数据来源

复用 `state.json` 里已有的两个数组，不引入新字段：

| 来源 | 字段 | 用途 |
| --- | --- | --- |
| 划线 | `Book.highlights[]`：`cfi` / `text` / `color` / `label` / `createdAt` | 引用块的正文、颜色、章节 |
| 书签 | `Book.bookmarks[]`：`cfi` / `label` / `createdAt` | 书签小节的条目 |

两者都只有 `kind === "ebook"` 的书才有内容——PDF / Markdown / 文本当前没有批注体系（PDF 批注属于明确不做的范围，见产品规格「非目标」）。所以这一期的实际受众是电子书。

## 3. 输出格式

````markdown
# 书名

作者：某某

12 条划线 · 3 个书签 · 导出于 2026-11-19 14:30

## 划线

> 第一段原文
>
> 第二行原文

—— 第三章 · 靛青

## 书签

- 第五章 · 11-19 14:31
````

约定：

1. **顺序按加入时间**。数组本身就是 push 顺序，与 `createdAt` 一致。按书中位置排序要先解析 CFI 的先后关系，代价不小而收益有限；「顺着他划的顺序读一遍」正是笔记的用法。这一点与侧栏列表相反（那边倒序、最近的在最上面），是刻意的：列表用于回看，导出用于成文。
2. **每条摘录用引用块，出处单独一行**。不选无序列表，是因为多行原文在列表里会让每一行都变成一个项，读起来支离破碎。
3. **颜色写在出处行**。导成纯文本后颜色本身没法保留，但颜色名能带上用户当时的分类意图（琥珀 / 橄榄 / 靛青 / 梅红 / 墨灰），成本只有一个分隔符。
4. **空小节不输出**。没有书签就没有 `## 书签`，不留一个空标题让人以为内容丢了。
5. **标题为空时落到「未命名文档」**，`author` 为空则整个「作者：」行都不出现。

## 4. 两个出口，一份内容

| 动作 | 去处 | 失败时 |
| --- | --- | --- |
| 复制 | `navigator.clipboard.writeText` | 明确提示「复制失败，可改用导出」，不静默 |
| 导出 | Rust `save_text_file` 弹系统保存框，写 UTF-8 无 BOM | 报出错误原因 |

两者都调用同一个 `buildMarksMarkdown()`。若各拼一套，「先复制看一眼」就不再能预览将要导出的东西。

取消保存**不是失败**：命令返回空串，前端据此不弹提示。

## 5. 边界

- **没有摘录就不出按钮**。空列表上挂一个必然导出空文件的按钮，比不挂更误导。工具区由页面自己判「本页有没有内容」，不由 `hasMarks()` 判整本书——否则「书签页空着但有一条划线」时会看到一行孤零零的按钮。
- **导出的是整本书**，不只是当前页签。按钮的 tooltip 写明「划线与书签」，避免用户以为在书签页点导出只会得到书签。
- **只取当前活动栏的书**。分栏时两栏可能是两本书，与侧栏列表同源（都走 `activePane()`），不会出现「看着 A 导出来是 B」。
- **文件名过滤非法字符**：`\ / : * ? " < > |` 与控制字符替换成空格，多余空白合并，标题截到 80 字。不这么做，保存框会在 Windows 上报错，而错误来自用户的书名，很难理解。
- **块级转义只处理行首**：行首的 `#`、`-`、`+`、`*`、`1.`、`1)` 加反斜杠。行中的符号不构成块级语义，转了只会多出一堆反斜杠。
- **不做**：导出整库、导出为 PDF / HTML / docx、按颜色筛选、自定义模板。

## 6. 模块划分

| 文件 | 职责 | 边界 |
| --- | --- | --- |
| `src/js/reader/export-marks.js` | 纯函数：`buildMarksMarkdown` / `suggestFileName` / `hasMarks` | 不碰 DOM、不发请求 |
| `src/js/reader/marks-tools.js` | 工具区 HTML 片段 | 只拼字符串，不绑事件 |
| `src/js/reader/marks-export.js` | 两个出口的副作用（调命令、写剪贴板、Toast） | 不发请求以外的事 |
| `src-tauri/src/commands.rs` | `save_text_file`：保存框 + 落盘 | 不掺和格式 |

把「输出长什么样」与「怎么落地」分开，是为了冒烟能**直接断言 Markdown 结构**，不必卷进系统对话框。

## 7. 验收

| 项 | 标准 |
| --- | --- |
| 结构 | 有划线时出现 `## 划线` 与引用块、出处行；无书签时没有 `## 书签` |
| 转义 | 原文 `- 列表开头` / `# 标题开头` 在导出里带反斜杠，普通行不带 |
| 回落 | 无章节名的划线落到「正文」；无作者时没有「作者：」行 |
| 文件名 | `A/B: C` → `A B C-摘录.md` |
| 入口 | 有摘录时计数行右侧两个按钮；摘录清空后两个页签都不再出现 |
| 一致性 | 复制得到的内容与导出逐字相同 |
